# 침해대응의 달인 · Incident Master

클라우드 침해사고 대응 순서를 실제 꼬치로 배우는 **BEAVER DAM 커뮤니티 부스 체험형 웹앱**입니다.

참가자는 사고 상황과 재료별 행동을 읽고 대응 순서를 생각해 꼬치를 만듭니다. 진행자가 실물 꼬치를 확인한 뒤, 필요할 때 정답을 공개합니다. 디지털포렌식 위크 2026 부스 운영을 위해 만들었습니다.

## 바로 실행하기

1. 이 레포의 **Code → Download ZIP**을 눌러 내려받거나 아래 명령으로 복제합니다.
2. 압축을 푼 폴더의 **`dist/index.html`**을 브라우저에서 엽니다.
3. 노트북 가로 화면에서 ‘게임 방법’을 확인하고 ‘랜덤 주문서 받기’로 시작합니다.

```sh
git clone https://github.com/Beaver-Dam-Community/Incident-master.git
cd Incident-master
```

로그인·회원가입·서버 설치가 필요 없습니다. 폰트와 그림이 포함돼 있어 오프라인에서도 실행할 수 있습니다. 옮길 때는 **dist 폴더 전체**를 유지해 주세요.

로컬 웹서버로 실행하려면 Python 3가 있는 환경에서 다음 명령을 사용합니다.

```sh
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 <http://127.0.0.1:4173/>을 엽니다. 웹으로 배포할 때도 `dist/` 전체를 정적 웹서버에 올리면 됩니다.

## 게임 진행

1. **게임 방법 확인**: 기본 대응 흐름을 알아본 뒤, ‘01 읽기 → 02 끼우기 → 03 완료’ 예시를 살펴봅니다.
2. **랜덤 주문서 받기**: 곧바로 한 미션이 시작되고 경과 시간을 셉니다. 시간 제한은 없습니다.
3. **실물 조립**: 참가자가 사고 요약과 재료별 행동을 읽고 실제 꼬치를 만듭니다. 정답 그림은 아직 표시하지 않습니다.
4. **진행자 판정**: 참가자가 ‘수습 완료!’를 외치면 실물 꼬치를 확인합니다. 틀리면 같은 미션으로 계속 도전합니다.
5. **정답 공개**: 진행자가 버튼을 누르면 타이머가 멈추고 걸린 시간과 정답 꼬치가 나옵니다. 자세한 해설은 ‘왜 이 순서일까요?’를 펼쳐 확인합니다.
6. **다음 팀 준비**: ‘처음으로’를 눌러 새 팀을 준비합니다.

- 한 팀 한 미션이며 난이도 구분, 재료 순서 입력, 자동 판정은 없습니다.
- 치즈와 베이컨은 납작하게 지그재그로 접어 **각각 독립된 한 칸**에 끼웁니다. 다른 재료를 감싸지 않습니다.
- 주문서에 따라 4~6개 재료를 사용합니다. 재료별 행동은 시나리오마다 달라집니다.
- 화면 아래의 작은 **시나리오 A~S 코드**로 진행자 답안과 연결합니다.
- 기본은 전체 19종입니다. 설정에서 시나리오 묶음을 고를 수 있습니다. 선택한 묶음을 모두 뽑은 뒤 다시 섞습니다.
- 새로고침해도 같은 브라우저에 현재 미션과 정답 공개 여부가 복원됩니다. 브라우저 저장이 제한된 환경에서는 복원이 제한될 수 있습니다.

## 기본 대응 흐름

게임 설명의 첫 화면에서 다음 여섯 가지 생각법을 안내합니다.

| 흐름 | 의미 |
| --- | --- |
| 막기 | 지금 진행 중인 피해를 멈춥니다. |
| 남기기 | 지우거나 바꾸기 전에 증거를 보존합니다. |
| 파악하기 | 원인과 피해 범위를 조사합니다. |
| 되돌리기 | 공격 흔적을 정리하고 정상 상태로 복구합니다. |
| 다시 못 오게 하기 | 침입 경로와 약한 설정을 보완합니다. |
| 확인하기 | 조치의 효과와 재발 여부를 확인합니다. |

이는 사고를 이해하는 기본 틀입니다. **사고 상황에 따라 순서가 달라지거나 여러 조치를 함께 진행할 수 있습니다.** 각 주문서의 정답은 해당 상황의 대표 대응 흐름입니다.

## 시나리오

2026-11-01 취합본의 제목·풀이·A~S 코드를 반영했습니다.

| 코드 | 묶음 | 개수 |
| --- | --- | ---: |
| A~E | 기본 클라우드 사고 | 5 |
| F~I | 추가 클라우드 사고 | 4 |
| J~O | 클라우드 사고 | 6 |
| P~S | AI와 클라우드 사고 | 4 |

취합본에서 바뀐 계정 탈취(A), 공개 링크(C), 랜섬웨어(E)의 정답 순서도 반영했습니다. P~S의 감싸기 조건은 회의에서 정한 독립 재료 방식으로 바꿨습니다. 검사·자동 만료·최소 권한·사람 승인은 관련 행동 전에 준비하고, 복구 검증은 복구 다음에 배치합니다.

시나리오는 교육용 게임 상황입니다. 실제 사건의 발생 사실이나 세부 연혁을 별도로 주장하지 않습니다.

## 파일 구성과 수정

| 경로 | 용도 |
| --- | --- |
| `dist/` | 브라우저에서 바로 실행하고 배포하는 웹앱 전체 |
| `dist/app.js` | 화면, 게임 설명, 진행 버튼 |
| `dist/game-engine.js` | 추첨, 진행 상태, 경과 시간 |
| `dist/typography.css` | 글꼴, 읽기 크기, 줄바꿈, 기본 흐름 카드 |
| `dist/assets/` | 로고, 재료 그림, 포함된 폰트와 폰트 라이선스 |
| `compiled-catalog.json` | 현재 시나리오의 제목·요약·재료 행동·정답·해설 기준 |
| `compiled-source-reference.json` | 취합본에서 추출한 검증용 원문 데이터 |
| `scenario-codes.json` | 시나리오 ID와 A~S 코드 연결 |
| `build_web_data.py` | 기준 데이터를 검증하고 `dist/scenarios.js` 생성 |
| `tests/` | 게임 동작과 취합본 반영 검증 |

시나리오를 바꿀 때는 `compiled-catalog.json`을 수정하고 아래 명령을 실행합니다. 코드를 바꾼다면 `scenario-codes.json`과 진행자 답안지도 함께 맞춰 주세요.

```sh
python build_web_data.py
```

검증은 Node.js 22 이상에서 실행할 수 있습니다. 별도 패키지 설치는 필요 없습니다.

```sh
npm test
```

검증 항목에는 19종의 제목·코드, 정답과 추가 인정 배열, AI 독립 재료 조건, 정답 숨김·공개, 무작위 추첨, 새로고침 복원, 타이머 시작·정지·초기화가 포함됩니다.

## 디자인과 자료

- 브랜드명은 **BEAVER DAM**, 게임명은 **침해대응의 달인**입니다.
- 파란 계열의 파스텔 UI와 둥근 카드, 실제 재료에 대응하는 SVG 그림을 사용합니다.
- 큰 제목·재료 이름에는 Jua, 설명·재료 행동·해설에는 Pretendard를 사용합니다.
- 로고는 BEAVER DAM 커뮤니티에서 제공한 자료입니다.
- [Jua](https://fonts.google.com/specimen/Jua)와 [Pretendard](https://github.com/orioncactus/pretendard)의 라이선스는 각각 `dist/assets/Jua-OFL.txt`, `dist/assets/Pretendard-OFL.txt`에 포함했습니다.
